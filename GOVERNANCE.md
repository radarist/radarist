# Governance

Radarist v0.1 is a maintainer-controlled reference prototype.

## Decision authority

The repository owner decides release scope, architecture, security posture,
roadmap, licensing, and whether an issue is accepted. There are no elected
roles, contributor tiers, voting rules, or delegated release authorities in
v0.1.

## Inbound channel

GitHub Issues are the sole general inbound project channel:

<https://github.com/radarist/radarist/issues>

Issues may inform maintainer decisions but do not create a delivery commitment.
The repository does not offer a pull-request or contributor workflow for v0.1.
Confidential vulnerability reports use the private path in
[SECURITY.md](SECURITY.md), not public issues.

## Releases

Maintainers publish snapshots after the documented quality gates and owner
review. A public tag or release is authoritative only when it exists in the
public repository; roadmap text and issue discussion are not release promises.

## Changes to this policy

Any future community governance model will be published here before it takes
effect. Until then, this document is the complete governance model.
